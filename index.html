Server produksi: tiap keputusan ada alasannya

Server ini menjalankan database dan web untuk produk di lembar 2. Saya merakit hardware-nya, memasang Proxmox VE 9, dan mengujinya seperti sistem produksi: mematikan container untuk memastikan situs tetap hidup, memindai port dari luar, dan menghitung apa yang terjadi kalau satu disk mati.

Tiga pelajaran yang saya bawa

  1. Uji dari luar, jangan asumsikan. bind-address saja tidak menutup semua port MySQL.
  2. Pasang mekanisme rollback sebelum mengubah firewall dari jarak jauh.
  3. Verifikasi arsitektur image sebelum menyalahkan hardware.
Spesifikasi
HypervisorProxmox VE 9.2
CPU / RAMRyzen 9 9900X · 32 GB
Disk2× NVMe 2 TB + 2× HDD 4 TB, ZFS mirror
Containerweb, redis, db (LXC)
DatabaseMySQL 8.4 LTS
AksesTailscale · Cloudflare Tunnel

Pekerjaan yang sudah diverifikasi

  1. Penyimpanan. Dua ZFS mirror, ARC dibatasi, kedua partisi boot terisi sehingga tetap boot walau satu NVMe mati.
  2. Isolasi. MySQL hanya di bridge internal; aplikasi menjangkaunya lewat NIC kedua. Firewall per container dan firewall host default-deny.
  3. Akses. Tidak ada port diteruskan ke internet. Tailscale dengan ACL, SSH hanya kunci, 2FA di web UI, fail2ban, pembaruan keamanan otomatis.
  4. Edge. Cloudflare Tunnel untuk aplikasi; Cloudflare Worker untuk halaman statis agar tetap hidup saat server dimatikan.
  5. Backup. Dump MySQL harian, vzdump semua container, snapshot ZFS, salinan off-site GPG. Penjaga backup memeriksa struktur dump, bukan ukurannya.
  6. Pemantauan. Dashboard buatan sendiri membaca satu aliran JSON lewat SSH: daya CPU, keausan NVMe, umur scrub, status backup. Tanpa port tambahan.

Prosedur kerja: dari brief sampai serah terima

Urutan ini yang membuat produk di lembar 2 bisa dirawat orang lain.

Keterangan tahap

  1. PRD sebelum kode. Setiap project dimulai dari dokumen singkat: siapa penggunanya, alur utamanya, dan apa yang sengaja tidak dibuat.
  2. Uji yang bisa diulang. Aturan bisnis penting punya tes otomatis. Tes yang butuh database ikut jalan di CI, bukan dilewati diam-diam.
  3. Aman sejak awal. Default-deny, rahasia di environment, 2FA untuk akun berkuasa, dan port diuji dari luar sebelum dinyatakan tertutup.
  4. Bisa diserahkan. README dan catatan deploy ditulis untuk orang berikutnya, termasuk jalan buntu yang sudah dicoba agar tidak diulang.
